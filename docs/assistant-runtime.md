# 工作台助手：Agent Runtime

助手在 Tauri 的 Rust 进程内运行。React 只负责流式消息、查询结果和操作预览；没有新增服务器、云数据库或后台守护服务。

## 一轮对话如何完成

1. 载入当前对话的目标、近期查询指代、操作状态及最近 24 条消息。
2. 请求 DeepSeek，并提供标准 `tools` 函数定义。
3. 模型可返回普通文字，或选择一个/多个工具。
4. 本地验证参数、调用真实 SQLite 查询或准备操作，将结果以 `role: tool` 和匹配的 `tool_call_id` 回传。
5. 模型可继续查询、修正参数、调整方案，直到回答完成或需要用户补充/确认。

普通聊天通常需要一次明确的工具决策加一次流式回答；业务问题取决于工具轮数。每轮最多 12 次模型调用、24 次工具调用、6 次工具失败，整轮超时 300 秒。普通工具同一参数最多调用 3 次；准备/修改/替换预览失败后，必须修正参数才能重试，原样重试会停止。同一预览工具遇到完全相同的错误 3 次也会停止并要求模型解释，避免空转。达到限制时已准备的预览保留。停止生成会取消当前请求，不会自动执行预览。

采用 DeepSeek 稳定 Chat Completions 的标准 Function Calling；不依赖 beta strict 模式、OpenAI 账户或飞书服务。参数即使来自模型，仍由本地校验。内部推理不展示，仅展示“查询工作台”“准备操作预览”等可核实的步骤。

## 业务工具

| 工具 | 用途 | 是否改变业务表 |
| --- | --- | --- |
| query_records | 实时查询项目、阶段、任务、日程、事件；筛选、分页、程序计算任务状态 | 否 |
| get_workload | 日期范围内的负荷、阶段、截止、事件、未完成工作及过期执行安排 | 否 |
| calculate_dates | 本地日历加减天数，跨月/跨年计算 | 否 |
| prepare_operation | 新建、修改、删除、归档、恢复及批量操作预览 | 否 |
| list_operations | 当前对话操作及最新手动修改 | 否 |
| revise_operation | 合并修改原操作，不覆盖未提到的字段 | 否 |
| present_operation | 在当前回复下重新展示同一表单，不改变字段、版本或暂停状态 | 否 |
| replace_operation | 原子生成替代方案并作废原方案，失败全部回滚 | 否 |
| set_operation_state | 暂停、继续、取消预览 | 否 |
| remember_intent | 保存本对话已经明确的目标与约束 | 否 |
| keep_operations | 明确选择闲聊、解释、只建议或必填信息需要澄清，本轮不生成新操作；已有预览保持原状态和位置 | 否 |

DDL 属于任务的截止字段。五类记录均支持查询、新增、修改、删除；项目与任务支持归档/恢复，完成/重新打开通过状态修改预览处理。任务和日程的完成状态始终独立。

模型没有保存业务记录、SQL、Shell、文件读取或外部网络工具。新增事项与现有对象的关联也需要用户核对。

除确认/取消按钮的真实回执反馈外，每轮首步要求模型选择工具，避免无待处理表单时也会出现只口头宣称新表单已生成的问题。纯聊天、只建议或需要澄清时选择 `keep_operations`，不查询业务数据、不移动表单，通常会多一次模型调用。这是明确操作意图的成本，不通过关键词规则替模型判断语义。工具返回当前操作的核实状态与“未写业务记录”标记；准备新表单时，上一项的已保存回执不能作为新表单的保存凭据。

## 语义补全与校验修正

工具字段采用明确的 JSON Schema 属性、类型、枚举和标题长度限制；各业务类型适用字段及跨字段约束仍由本地程序校验。更新未提及字段不发送，不用可选字段的空值覆盖手动内容。

- 模型可以根据明确意图拟定记录标题，不必为了标题重复询问用户是否创建。新建关联日程未提供标题时，程序可沿用已核实的关联任务标题（包括同组新建任务的引用）；不适用于修改已有日程，不覆盖用户明确提供的标题。
- 程序将沿用的标题固化到操作计划中，并在预览返回 `inferred_fields`，供模型简短说明来源。确认按同一计划校验，不因关联任务改名而悄悄改变预览标题。
- 未提供的备注、结束时间、任务截止等可选信息保持默认空值。新建任务不会从执行日期推导截止；下午/晚上不会推导具体小时；精确日程只要求开始时刻，结束可留空。
- 围绕已有工作或考试安排执行时，读取开启且未明确要求独立日程，应先按主题查询任务；唯一明确匹配可关联并说明，多个候选先澄清，未找到可安排独立日程。不查询无关项目来猜新任务归属。
- 日期、关联对象等业务事实不可编造。有实质歧义的必填信息应先从上下文查找，仍不能确定才询问；只建议、不创建的请求不生成操作。
- 校验错误注明原提交顺序中的第几项、步骤 key、业务类型和字段及修正建议，不再将空标题与长度超限混为一个错误。失败结果同时携带 `recovery` 指引、同错次数和是否可重试；模型修正出错字段，保留用户已明确的意图及其它字段。
- 失败不会写入业务表，也不会覆盖原有效预览；所有成功修正后的预览仍需用户点击确认。

## 独立操作账本

迁移 011 新增 `assistant_operations`、`assistant_runs`、`assistant_steps`、`assistant_context`，保留已有表和数据。操作不依赖回复正文，断网、停止生成、切页、重开程序都不会把待确认内容变成正式记录。

生命周期：

```text
待确认 ⇄ 已暂停
  │          │
  ├──────────┴──→ 已取消
  │
  └─ 用户点击确认 → 校验与事务 → 已保存（实际结果回执）
```

每组最多 50 项，当前对话最多 12 组未结束操作。修改预览包含原记录、修改后记录及级联影响；所有字段由本地白名单限制。

“确认并保存”只传操作 ID 和版本号。Rust 在单连接 SQLite 事务内：

1. 校验操作仍待确认、版本相同；已保存的重复确认返回原回执。
2. 核对全部原记录与级联内容，发现其它页面修改、删除或新增子项就拒绝整批保存。
3. 重新检查业务字段、日期、关联、防重及预览与计划的一致性。
4. 执行整组改动，记录实际回执，同时标为已保存；任何错误全部回滚。

删除项目会删除所属阶段、任务及任务日程；删除任务会删除关联日程；删除阶段保留任务和日程，仅解除阶段关联。预览会展示影响。归档保留状态与历史。

手动编辑使用现有日期、时间和下拉控件；有效修改自动保存，发送下一条消息、切换对话和确认前会等待写入完成。空标题等无效中间内容会提示，不能提交。聊天修改按步骤合并指定字段，保留手动备注。冲突后可要求助手重新查询并生成最新预览。

## 表单位置与方案替换

迁移 012 增加 `assistant_operation_presentations`，为旧操作补齐原显示位置；`assistant_operations.superseded_by` 记录替代关系。业务操作 ID 与聊天中的显示位置独立，状态和防重规则保持有效。

- 修改同一组预览成功后，最新版自动放在本条回复下；旧位置只读，不能再次编辑或确认。
- “表单在哪、看不到、再生成一个”默认调用 `present_operation`，重新展示原组，保留手动字段、业务版本及暂停状态，不创建另一个任务。
- “原方案不要了，作废后重做”调用 `replace_operation`。新方案校验、生成与旧组作废在同一事务中；失败不会丢失原方案，成功后旧确认请求被拒绝。
- 单纯读取操作不会移动表单；手动字段自动保存也不会移动当前编辑器。
- “查看最新版”定位唯一编辑器；多次替换的引用会沿关系定位最后一份方案。
- 显示位置保存在 SQLite，重开后恢复；回复途中断网导致消息未保存时，表单在恢复区域保留。界面用同一读取事务加载操作、显示位置和执行步骤，并丢弃过期刷新结果。

模型不具备检查用户滚动位置、页面刷新状态或通知区的能力，不得以此解释界面问题。未指定归属的新建任务默认独立，不查询无关项目/阶段来猜测归属。

## 事实与上下文

- 每次查询从 SQLite 获取同一读取事务的快照，不复用上轮数据库副本。
- 逾期、截止剩余天数、日程总数、已执行数、待执行数由程序计算。
- 仅日期的任务在当天结束前不算逾期；具体截止时刻按用户本地时间比较。
- 日程执行完成保留历史，不自动完成任务；有历史且待执行 0 次不能称为“没有关联记录”。
- 已明确目标与约束独立保存，近期查询保留对象 UUID，短句指代可重新查询。
- 操作的最新版本和手动字段优先于历史助手文字。工具失败会回传给模型，使其能调整参数，不代表操作成功。
- 程序最新快照放在历史消息之后，降低模型抄回旧字段的风险；修改/替换预览的增量字段定义明确要求省略“保留不变”的字段，由本地合并保留最新值。
- 不承诺任意自然语言零误判。目标有实质歧义应澄清；用户已经限定范围后不应反复追问。

## 隐私和展示

开启读取后按需发送查询结果，不预先上传整库；查询可明确选择归档范围。每次最多返回 100 项，结果注明总数与是否还有下一页；长备注会明确截断。负荷范围最多 62 天，未完成工作摘要最多 100 项。

关闭读取会在 Rust 层拒绝业务查询和模型对已有记录的修改准备，但仍能普通聊天、创建独立事项、讨论当前对话已经分享的预览。关闭不会抹除历史消息已经引用的内容。需要隔离此前资料时新开对话。

API Key 仍只保存在 Windows 凭据管理器。对话、目标、执行步骤和操作预览保存在本机 SQLite；业务 JSON 导出不包含助手历史、API Key 或操作账本。删除对话会移除其账本及步骤，已确认业务记录保留。

正文使用 GFM Markdown：段落、加粗、标题、列表、表格、引用、代码与复制代码。原始 HTML 不执行，远程 Markdown 图片不自动加载。查询卡片注明查询时间，历史结果不是实时订阅。动画继续使用现有 SWUST 缓动与减少动态效果偏好。

旧版已有消息与表单保留，可按原表单确认/取消；新的业务操作使用独立预览。旧版未确认表单尚未自动迁移为新操作账本。

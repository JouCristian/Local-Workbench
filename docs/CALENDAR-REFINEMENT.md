# 日程与首页修复

本轮按用户最新要求调整，取代早期「首页不允许分区滚动」的设计。

## 行为

- 日程问号浮层在按钮附近定位。每个过渡页面独立持有按钮引用，避免旧页面退出清空新页面引用后浮层落在(0,0)。保留边缘避让与原有渐入渐出。
- 到期任务分三种：无任何日程则「待安排＋截止信息」；安排在其他日期则「截止提醒」；当天已有执行则在执行条目内展示截止信息，不重复创建一行。DDL不转换为执行时间。
- 任务行右侧日历入口改为「任务日程」，统一查看、连续新增、编辑和移除该任务的全部安排。日期、时段、精确起止时间分别修改，标题备注按需展开，最后一次保存。
- 移除已有日程先留在草稿，可撤回；保存时确认删除数量。取消窗口不写入草稿。
- Rust单连接事务保存整组日程，重复、无效日期时间、过期版本或写入失败时整批回滚。仅替换当前任务关联的日程；任务、DDL和其他任务数据保留。没有新增数据库迁移，仍为版本6。
- 精确日程使用项目色浅填充、彩色边缘；独立安排使用主色。长日程滚动后标题与完成按钮保持可见。没有填结束时间时，显示块的最小高度不写入虚构时间。
- 首页左侧为00:00–23:00时间表，模糊时段、事件和截止提醒位于上方，同一内部滚动区均可访问；默认靠近当前小时。右侧倒计时限制高度、内部滚动。两处均固定预留12px槽位。
- 桌面根据可用高度适配列表，保留底部项目；短窗口、窄屏或项目很多时允许整页滚动，不裁掉功能。

## 验证记录

43项前端测试、8项Rust测试通过，包含跨日截止语义、批量日程无效输入、版本冲突与数据库写入失败回滚。

实际Tauri窗口验证通过：连续创建3条日程、已有多日程编辑、防重且无部分写入、取消和确认移除、DDL保留、日期切换后帮助浮层靠近按钮、24小时可滚动、明暗色块、320px窄屏与减少动态效果。

1380×920、41项未完成任务的专项场景下，今日与倒计时各自滚动，预留槽宽12px；主页面`scrollHeight=clientHeight=834px`。这些结果针对该场景，不代表任意高度或任意项目数量都无整页滚动。

测试只操作随机UUID记录，结束后逐表比较业务数据。截图及报告位于Git忽略的`artifacts/calendar-refinement/`。

Windows正式EXE与NSIS安装包已构建成功。正式EXE在WebView网络离线条件下启动两次，验证新命令原子保存两条执行日程，关闭整个进程后两条仍然存在；任务完成、归档、恢复和删除联动均通过，外部网络请求与脚本错误为0。本轮未执行覆盖安装。

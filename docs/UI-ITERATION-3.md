# UI 与交互迭代 3

本轮根据用户反馈同时调整展示与业务规则。页面结构、离线 SQLite 与固定滚动槽保留；新增第四版数据库迁移支持软归档。修改前已在本机 artifacts/ui-iteration-3 中保存完整 JSON 与 SQLite 备份，该目录被 Git 忽略。

## 界面与动画

- 页面、内容分区只渐显/渐隐，无位移和弹性。侧栏保留平滑过渡，导航/日期选中沿用共享底色。
- 阶段改为显式 Disclosure：只对高度和透明度做 280ms 非线性补间，保持 height=0，不依赖 details 结束时的原生布局切换。
- 下拉改为手动控制 top layer 生命周期：退出期间冻结位置与布局，只淡出；完成后隐藏。避免关闭时因布局方向/层级改变产生错位和闪烁。
- 弹窗将焦点放在标题，不默认聚焦输入框。下拉搜索不自动聚焦，不绘制蓝框。输入、日期、搜索等控件只保留一个描边所有者，border 与柔和蓝色 glow 渐变，不叠加 outline。
- 取消已完成任务时，行不会先恢复全亮度再消失；退出高度和透明度单调下降。
- 某时段最后一项完成时，时段标题和任务作为一个整体收拢，避免子项收起后突然移除标题和留白。
- 保留减少动态效果支持、弹窗键盘边界和固定 12px 滚动槽。

## 分类与归档

独立任务、项目是并列入口。「全部项目」仅包括真实项目，不包含独立任务。独立任务直接显示截止日、可选截止时间、执行日期和模糊/精确时段；没有 DDL 明确标为未设置，绝不从执行计划推导截止时间。

项目、任务新增可选 archived_at。归档是可恢复的隐藏操作，不修改任务完成状态、不删除阶段和日程。已完成任务可从行尾归档；编辑任务/项目窗口也有归档操作，未完成内容归档有确认。在归档页恢复后保持原状态。项目归档一并隐藏其工作内容，独立归档的任务不会因恢复项目而被意外恢复。已归档完成成果仍计入项目/阶段进度。

## 防重边界

- 任务：同一项目/独立分类、同一阶段、标准化后的同名活动任务会被阻止重复创建。忽略空格、大小写与全半角的意外差异。不同项目/阶段的同名事项允许存在；归档历史不阻止新工作，恢复时若与活动任务冲突会提示处理。
- 日程：同一任务、同一日期、同一模糊时段，或同一精确开始时刻，只允许一个执行安排；修改结束时间属于编辑同一次执行。无关联日程按标准化标题识别。不同日期/时段/开始时刻保留，同一时间的不同任务仍可重叠。
- 读取既有相同日程时，时间线和日期条合并显示；原记录不静默删除。编辑相应日程可查看重复记录、日期时段和备注，经确认后移除指定重复项。
- repository 统一执行验证；SQL 使用单条带条件的 upsert 防止并发窗口绕过常见重复检查。旧 JSON 的重复日程仍可原样恢复，保留历史记录并合并展示。

## 架构与兼容

- domain/records.ts：活动视图、身份、防重和非破坏性日程合并。
- data/statements.ts：可测试的原子 SQL 构建；repository 负责校验、串行化与持久化。
- state.tsx：共享归档操作与状态同步，重复输入作为局部表单冲突处理。
- components/Disclosure.tsx、Controls、Items、Timeline：分别管理单一几何动画和焦点边界。
- 004_archives.sql：为 projects/tasks 增加 nullable archived_at 及索引。前三个迁移不改写。
- Rust 恢复事务复用可测试的写入函数，旧 version=1 JSON 允许缺少归档字段，新导出保留归档；失败回滚并保留原内容。

## 已保留的边界

尚不实现循环任务和复杂拖拽日历。旧重复记录保留，需在编辑界面明确选择清理；这避免未经审阅丢失日程备注。归档不是加密或异地备份，重要内容仍应定期导出。
